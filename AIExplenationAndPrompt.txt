# Bestaat dit al?

**Ja, maar niet precies zoals jij het beschrijft.**

Er zijn een paar zeer interessante voorbeelden.

## 1. Roblox

Waarschijnlijk de grootste vergelijking.

Roblox Corporation heeft Roblox Studio, waarmee gebruikers games kunnen bouwen, testen en publiceren. Studio bevat onder andere templates, een 3D editor, physics, multiplayer en scripting. ([Creator Hub][2])

Het grote verschil:

**Roblox**

```text
Creator
   ↓
Roblox Studio
   ↓
Roblox platform
   ↓
Roblox servers
   ↓
Players
```

Jij wilt eerder:

```text
Creator
   ↓
YOUR ENGINE
   ↓
GAME FILE
   ├── Local
   ├── LAN
   └── Dedicated server
          ↓
        Players
```

Dat is een fundamenteel verschil.

Je gebruikers zouden dus bijvoorbeeld kunnen zeggen:

> "Ik heb mijn survival game gemaakt. Ik wil hem op mijn eigen Linux VPS hosten."

En dan:

```bash
myplatform-server ./MySurvivalGame
```

Klaar.

---

# 2. Core

Manticore Games heeft **Core**, en dit komt misschien nóg dichter bij jouw idee.

Core is expliciet gericht op gebruikers die multiplayer-games willen maken zonder vanaf nul een game-engine te bouwen. Het bevat bijvoorbeeld templates voor survival, dungeon crawler, battle royale, racing enzovoort. ([Core Games][3])

Het ondersteunt ook een community van door gebruikers gemaakte games. ([Manticore Games Support][4])

Maar:

> Core is een gesloten commercieel platform.

De servers/infrastructuur zijn onderdeel van Core. ([docs.coregames.com][5])

Dat is precies waar jouw project zich zou kunnen onderscheiden.

---

# 3. Luanti

Deze is **heel belangrijk om te bekijken**.

Luanti (vroeger Minetest) is een open-source voxel game creation platform. Je kunt verschillende games spelen, games/mods maken en lokaal of online multiplayer spelen. ([luanti.org][6])

Het heeft bovendien een interessant concept:

```text
Luanti
   │
   ├── Game A
   ├── Game B
   ├── Game C
   └── Game D
```

En servers kunnen de benodigde content automatisch aan clients leveren. ([wiki.minetest.org][7])

**Dit is architecturaal erg relevant voor jouw idee.**

Maar Luanti is primair een **voxel-engine**.

Jij wilt iets veel algemeners:

```text
2D platformer
       +
3D survival
       +
racing
       +
RPG
       +
tower defense
       +
board game
       +
???
```

Dat maakt jouw probleem aanzienlijk moeilijker.

# Multiplayer zou ik vanaf het begin ontwerpen

Niet eerst:

> singleplayer → later multiplayer

Dat veroorzaakt enorme problemen.

Maak het model vanaf het begin:

```text
                 GAME
                  │
         ┌────────┴────────┐
         │                 │
       CLIENT             SERVER
         │                 │
       Render             Logic
       Input              Physics
       UI                 AI
                          Game State
```

De server is authoritative.

Bijvoorbeeld:

```text
CLIENT
"Ik klik attack"

       ↓

SERVER
"Is deze speler werkelijk
in range?"

       ↓

SERVER
"Ja → enemy -20 HP"

       ↓

CLIENT
"Enemy health changed"
```

Dat maakt later dedicated servers veel eenvoudiger.

Godot ondersteunt hiervoor high-level multiplayer en dedicated-server deployments. ([Godot Engine documentation][1])

# Jouw game-format

Een heel belangrijk onderdeel zou een eigen gameformaat zijn.

Bijvoorbeeld:

```text
MySurvivalGame/
│
├── game.json
├── world/
├── entities/
├── scripts/
├── assets/
│   ├── textures/
│   ├── models/
│   ├── sounds/
│   └── animations/
│
└── server.json
```

`game.json` zou bijvoorbeeld kunnen bevatten:

```json
{
  "name": "My Survival Game",
  "version": "1.0",
  "engine": "1.0",
  "gameType": "survival",
  "maxPlayers": 16,
  "networkMode": "server-authoritative"
}
```

Maar je visual logic kun je bijvoorbeeld serialiseren als:

```json
{
  "event": "player_enter_area",
  "conditions": [
    {
      "type": "time_of_day",
      "operator": "equals",
      "value": "night"
    }
  ],
  "actions": [
    {
      "type": "spawn",
      "entity": "zombie",
      "amount": 3
    }
  ]
}
```

Dat betekent dat een game **data** is.

Niet:

```text
MyGame.exe
```

maar:

```text
MyGame/
    game definition
    assets
    logic
    configuration
```

Dat is een enorm voordeel voor een open platform.

## En ik denk dat je idee nóg interessanter kan worden

Ik zou het niet positioneren als:

> **"een game engine voor beginners."**

Maar als:

> **"een open-source platform waarop iedereen zijn eigen games kan maken, publiceren en hosten."**

Dat verschil is belangrijk.

Want dan wordt jouw eigen software uiteindelijk maar de **infrastructuur**.

Iemand anders kan vervolgens een:

* Minecraft-achtige survival game
* Pokémon-achtige RPG
* 2D platformer
* FPS
* racing game
* horror game
* RTS
* roguelike
* multiplayer party game

maken **zonder dat jij die games zelf hoeft te programmeren**.

En doordat de games uit data/components bestaan, kan iemand anders zelfs nieuwe componenten/plugins voor het platform schrijven.

Dat begint dan eigenlijk op een **open-source Roblox + game engine + Steam Workshop + dedicated-server ecosystem** te lijken.

**Als je dit serieus als project wilt aanpakken, zou ik als volgende stap niet meteen code schrijven.** Ik zou eerst de **architectuur van het platform ontwerpen**: welke projecten, entities, components, visual-scripting nodes, game files, client/server-communicatie en plugin/API's je nodig hebt. Dat kan ik vervolgens concreet voor je uitwerken tot een **technische architectuur + mappenstructuur + database/model + MVP-roadmap**, specifiek gericht op C#/.NET + Godot.
